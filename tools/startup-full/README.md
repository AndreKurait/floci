# Full-selection startup measurement

Fork-only diagnostic, pinned to the current Quarkus 3.40.1.1 framework class fingerprints. It does not cache indices or change test resources, test assertions, source, heap size, shard assignment or framework results.

The workflow copies the current five-shard CI selection, compile, class-completeness, prefetch and direct Surefire commands. Each shard runs on an independent plain and recorded runner, with the existing 25-minute job and 1200-second fork deadlines. Both modes enable build metrics. Instrumentation records actual index lifetimes and class loader identities, nested monotonic spans and each profile's build metrics. Unsupported framework classes fail closed. Compare interval unions, not sums of overlapping spans. Heap pool high-water marks are separate pool observations, not a simultaneous process peak.

Artifacts retain original source identities, CPU model, compiled class hashes, exact test cases and XML counts, and recording completeness. Only the source-confirmed TestImages utility may lack an XML report. Skips are retained, not converted into successes. A timeout or assertion failure is a failed experiment, never partial full-suite proof.

The plain and recorded jobs can run on different CPU models and physical hosts. A single pair does not establish causal overhead or speedup. Prior local two-profile ABBA results have separate attribution. This experiment measures the full selector and multiple profile preparation before the first application startup log. It does not establish native compilation, live AWS parity or completion of the canonical development image.

The compile and test commands retain structured elapsed, child user/system CPU and maximum-child RSS receipts. CPU divided by wall time estimates average occupied cores, not thread counts. Recorder intervals overlap: use interval unions before attributing time. Background Docker image prefetch is separate. Both modes enable build metrics, unlike an uninstrumented normal CI run. Ten independent hosted runners cannot establish causal improvement or recorder overhead. The aggregate job requires identical inputs, disjoint complete five-shard inventories, successful per-job compiled/source checks and matching executed case/skip identities across modes. Missing artifacts fail coverage.

Fork arguments are configured before test compilation and their POM digest is checked again before and after test execution. Changing the POM after compilation can invalidate the serialized Quarkus dependency model, so such preliminary local attempts are excluded. Selection and compilation have separate process receipts; discovery/index and per-profile augmentation are nested inside the test process. Existing application/resource logs and test XML remain available, but this recorder does not yet provide a dedicated span around every test-resource start method. No complete resource-start attribution is claimed.
